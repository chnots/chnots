# Toent 功能说明

`toent` 是待办与时间事件模块，负责把笔记中的任务/时间描述转换为可查询、可展示的日程数据。

## 标记方式
```markdown
# [TODO !A] 这是一个代办
; EVENT: 2020-12-29 12:13:14 +8:00 ,15M *3w =12t
```
`TODO !A` 代表整个任务的状态，只有整个任务中的所有重复任务都完成时，才能被标记为完成

EVENT 的标记格式说明
- Event 主要分为5部分
    - start: event 的开始时间，前面没有任何标记
    - alert: 每次开始之前的提醒，以 `,` 标记
    - interval: 间隔多长时间进行一次，类似 org-mode 的重复任务，但是我们这里使用 "*" 和 `**`
      `*` 代表常规重复， 类似 org-mode 的 "++"
      比如： `*1d` 一天， `*1w` 一周, `*1m` 一个月, `*1M` 一分钟
    - interval_end: 每次重复中的任务多长时间之后完成，以 `*=` 标记
    - end: 整个事件的终止，代表这个整个时间事件的 deadline, 以 `=` 标记
      - `=1y1m1d` 一年一月零一天后停止
      - `=10t` 重复十次后终止
      - `=2025-12-12 12:00:00` 代表 2025 年 12 月 12 日 中午十二点停止
  举例 `2024-12-12 12:00:00 ,15M *1d =2025-12-12` 代表从 2024-12-12 中午十二点开始，之后一天重复一次，任务开始十五分钟前有闹钟，截止到 2025-12-12 终止。


## 主要是做什么的

- 从 Markdown 内容中识别 TODO 与事件语法。
- 将解析结果结构化存储为任务、事件、实例三类数据。
- 生成可展示的时间实例，用于日程视图和统计。
- 提供查询、计数、过滤等能力，支持时间范围与完成状态筛选。

## 核心特性

- 写作即计划：用户在正文里写任务和时间，即可自动进入日程系统。
- 三层数据模型：任务定义、事件定义、时间实例分层管理。
- 实例化机制：将文本定义转为具体可展示的时间点。
- 日历视图支持：可在列表、周、月等视图查看安排。

## 典型使用场景

- 在笔记里写“TODO + 时间”后自动生成日程事项。
- 以周/月视图查看近期任务分布与完成情况。
- 按时间区间统计待办数量，辅助计划复盘。

## 与其他模块的关系

- `mdwt` 负责输入载体（Markdown 正文）。
- `toent` 负责解析、落库、实例化与日程查询。
- `chnot` 负责把这些内容统一组织在笔记体系中。

## Commit 与 Search 流程（产品说明）

`toent` 的核心目标是：用户只要在笔记里写任务和时间，系统就能自动形成可管理、可检索的日程数据。

### Commit：从“编辑内容”到“日程更新”

当用户保存笔记，或在日程页切换任务状态（如 TODO -> DONE）时，系统会自动完成以下动作：

1. 识别笔记中的任务状态与时间规则。
2. 更新任务定义（是否有时间、是否为待办）。
3. 生成或更新任务实例（用于列表/周/月展示）。
4. 对重复任务自动推进下一次待办（例如完成一次后自动出现下一次）。
5. 若内容没有实际变化，则不重复写入，避免脏数据。

这意味着：**用户只需要维护笔记内容，日程数据会自动同步。**

### Search：从“筛选条件”到“可展示结果”

当用户在 Toent 页面进行查询时，系统会按以下逻辑返回结果：

1. 根据时间范围筛选任务。
2. 根据完成状态筛选（已完成 / 未完成）。
3. 支持关键词与标签联合筛选。
4. 可选包含“无具体时间”的待办事项（如仅有 TODO 没有 EVENT）。
5. 对重复规则进行补算，确保未来应出现的事项也能展示。
6. 最终按时间顺序稳定输出，保证列表、周视图、月视图一致。

这意味着：**用户看到的是“当前可执行的完整日程”，而不是零散数据片段。**

### 用户价值

- 写作即计划：在笔记中写任务即可进入日程系统。
- 状态可追踪：任务状态变化会反映到后续计划。
- 查询更完整：支持时间、状态、关键词、标签组合检索。
- 视图一致：列表/周/月的数据口径统一，便于管理与复盘。
