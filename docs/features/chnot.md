# Chnot 功能说明

`chnot` 是整套笔记系统的“目录层”和“调度层”。
它本身不保存正文细节，而是负责描述一条笔记是什么、放在哪里、是否归档、是否置顶，以及如何被组织和检索。

## 主要是做什么的

- 统一管理笔记元信息：类型、空间、归档状态、置顶状态、时间版本。
- 作为多内容类型的入口：同一套笔记体系下可挂载文本、图形、文件、表格、会话等不同内容。
- 提供 thread 结构能力：支持父子笔记关系、顺序调整、子项移除。
- 提供统一搜索入口：可按关键词、标签、类型、空间、归档状态检索。

## 核心特性

- 多类型统一：通过笔记类型字段抽象不同内容形态，前端可按类型动态渲染。
- 元信息与内容解耦：`chnot` 专注索引和组织，具体内容由各业务模块处理。
- 线程化组织：支持把多个笔记串成可排序的上下文链路。
- 面向列表和检索优化：批量查询、过滤条件组合、默认归档过滤。

## 典型使用场景

- 在同一个空间中管理多种笔记类型，并用统一列表展示。
- 创建“主笔记 + 子笔记”结构，用于项目拆解、专题串联。
- 在全局搜索或局部搜索中快速定位目标笔记。

## 与其他模块的关系

- `chnot` 负责“索引与编排”。
- `mdwt / graph / kfile / ktab / llmchat` 负责“具体内容”。
- 用户看到的是一条笔记，系统内部则是 `chnot + 内容模块` 的组合。
